# 功率恢复与任务评价修复基线

本 fork 用于“智算中心算力负荷与电力负荷协同调度研究”。本次记录固定已经验收的基础修复，后续 HGTA＋HAPPO 等方法改动应在这个基线上单独比较。本次没有引入新调度算法，也不构成新方法有效性的证据。

上游起点为 [`ea50bd5`](https://github.com/nccp199/flexdc-sim/commit/ea50bd582b5d1b55fcb09ea46899fa9d325cce3b)。代码分三步记录：

3. [`cfe381e`](https://github.com/nccp199/flexdc-sim/commit/cfe381e149a05e69ebc96f6960d8ba58b2646aa6)：统一固定任务批次的三状态评价、报告与任务期限罚分。

## 已完成的两项修复

**功率恢复。** 原逻辑在不再需要限功率时只更新估算值，已经运行的节点可能继续停留在旧功率。现在每轮给活动节点明确下发功率指令，再按原算法施加必要限制；空闲节点保持空闲，新启动任务纳入计算。实际功率仍按原时序生效，进度更新顺序未改变。

**任务评价。** 对同一评价批次，统一计算截止时间：

```text
deadline = arrival_time + (1 + qos_constraint) * min_execution_time
```

| 状态 | 定义 | 如何进入评价 |
|---|---|---|
| `on_time` | 在截止时间内完成，含恰好按期完成 | 确认成功 |
| `late` | 已错过期限，包括未完成的任务 | 确认超时；晚完成也不改回成功 |
| `pending` | 尚未完成且期限未到 | 只给超时率上下界，不计作成功或失败 |

有待定任务时，下界为 `late / total`，上界为 `(late + pending) / total`。全部判定后，按任务类型分别计算 `late / total`，送入原 SoftPlus 罚分公式；任务期限及 `beta/rho/delta` 不变。无样本的类型显示 `no_samples`，不会被当作零超时；优化器拒绝不完整或无样本的最终分数。

默认评价原配置时段 `[0, simulation_duration)` 内到达的任务，包括时间 0 的预填充任务。观察终点按最宽任务期限预先确定，并向上取整到整小时，以沿用原项目按小时计费的逻辑。当前配置评价第一小时的任务，观察至两小时；第二小时仍正常接收任务、限制功率并计费。

```ini
[qos_evaluation]
cohort_start = 0
cohort_end = 3600
```

保存配置时保留评价区间和实际运行长度，回放不会重复延长。电力信号不足时明确报错。原生工作负荷生成器按完整观察长度重新生成输入，所以本次两小时输入与历史一小时输入不同；跨算法和修复前后比较必须使用同一份两小时输入。

正式结果查看 `qos_summary.csv`、`qos_task_status.csv`、`qos_evaluation.json`。带 `_at_cohort_end` 后缀的文件保留原时段结束时的待定状态。旧完成任务分位数、平均减速和 `QoSDegAvg.csv` 保留作诊断，不再作为最终任务期限达标判据。

## 重跑检查

当前已验证环境为 Python 3.10，NumPy 2.2.6、pandas 2.3.3、SciPy 1.15.3、pytest 7.3.2、wandb 0.19.11、tqdm 4.67.3。安装项目及依赖后，从 `src/peacsim` 运行测试，以保持原项目测试所依赖的工作目录：

```bash
cd src/peacsim
PYTHONUTF8=1 WANDB_MODE=disabled python -m pytest ../../tests ../../reports/reproduction_20261104/scripts/test_correctness.py -q -rsx
```

完整实验脚本需要两个独立代码目录：`--repo` 指向当前版本，`--baseline` 指向功率修复提交 `0f53d8d` 的副本。两个目录均使用同一 Python 环境；输出目录必须是新目录。

```bash
python scripts/validation/run_qos_validation.py \
  --repo /path/to/current-checkout \
  --baseline /path/to/power-fixed-checkout \
  --output /path/to/new-validation-output
```

该脚本使用随附的固定配置，生成匹配的两小时工作负荷，检查物理轨迹、任务批次、状态数量、重复运行、罚分和最优方案回放。它会写入独立输出，不需要 GPU；云同步目录建议使用独立副本运行。

## 后续开发边界

- 多节点完成判断暂缓。原生同步控制的测试未发现节点分叉；引入分区、异构控制或独立智能体后，需要重新定义任务完成条件与节点释放规则。
- 跟踪误差公式中已确认的时间对应问题未修改。现有原生跟踪指标不能作为未经复核的最终论文结论。
- 已验证的正式路径是常规模拟和基于任务期限的 SA 评价。遗留 `gradient_descent.py` / `gradient_descent_collab.py` 拟合式优化器未迁移，不可把其旧分数当作新口径。
- `flex-resource` 的资源可用性罚分保留原业务含义，不与任务超时率混同。
- HGTA＋HAPPO、可独立调度的计算分区及能源侧扩展均未实现。后续比较应固定工作负荷、评价批次、观察时间和罚分权重，分别记录环境变化与算法变化。
